# 场景 001：按内容整理和重命名文件

## 状态

候选场景，用于演示场景分析方法。它是否作为公司第一个功能，需要等待公司任务筛选结果。

## 1. 使用人员和问题

可能的使用人员：

- 行政；
- 财务；
- 销售；
- 项目管理；
- 需要维护大量资料的业务人员。

常见问题：

- 文件名来自不同人员，格式不一致；
- 只能打开文件后才知道内容；
- 批量重命名耗时；
- 修改出错后难以恢复；
- 同名文件容易覆盖。

## 2. 当前人工步骤

1. 打开文件夹；
2. 逐个打开文件；
3. 判断日期、主题和类型；
4. 按约定格式重新命名；
5. 处理同名文件；
6. 检查是否遗漏；
7. 必要时建立新旧名称对照表。

## 3. 输入和输出

### 输入

- 用户授权的文件夹；
- 命名规则；
- 支持的文件类型；
- 是否允许修改子目录；
- 是否需要按类型移动文件。

### 输出

- 重命名预览；
- 无法判断的文件；
- 文件名冲突；
- 用户确认后的修改结果；
- 新旧名称对照表；
- 失败和跳过记录。

## 4. Agent 的工作

- 根据文件内容和属性判断主题；
- 从内容中提取日期和类型；
- 按命名规则提出新文件名；
- 对无法判断的文件说明原因；
- 根据用户补充信息修正预览。

## 5. 普通程序的工作

- 限制工作目录；
- 列出文件；
- 解析文件内容；
- 校验文件名；
- 检查同名冲突；
- 展示修改预览；
- 等待用户确认；
- 执行重命名；
- 保存操作记录；
- 失败时恢复或保留原文件。

模型不能直接决定是否允许访问目录或覆盖文件。

## 6. Pi 的使用

### 可以复用

- AgentSession；
- Tool 调用；
- Session 保存和继续；
- Agent 事件；
- 现有 `read`、`find`、`ls` 等文件工具的设计；
- Skill 用于保存命名方法和业务规则。

### 需要新增

- 面向办公文件的元数据读取；
- Word、PDF、Excel、PPT 等内容解析；
- 重命名预览；
- 产品级审批；
- 操作记录和恢复；
- 文件结果页面。

## 7. 建议的 Tool

第一版可以拆成：

- 列出工作目录文件；
- 读取文件元数据；
- 提取办公文件文本；
- 生成重命名预览；
- 执行已批准的重命名。

最后一个 Tool 只能接受已经由产品审批过的操作列表，不能让模型临时追加路径。

## 8. 主要风险

| 风险 | 处理 |
|---|---|
| 访问目录外文件 | 程序限制工作目录 |
| 文件名判断错误 | 先预览，允许人工修改 |
| 同名覆盖 | 执行前检查，默认停止 |
| 批量修改错误 | 小批量试运行，保留记录和备份 |
| 文件无法解析 | 保留原名并说明原因 |
| 文件被占用 | 跳过并记录 |
| 重复执行 | 检查当前文件名和任务运行记录 |

## 9. 验收

### 正常案例

- 文本中日期、主题、类型明确；
- 生成的名称符合规则；
- 用户确认后完成重命名；
- 对照表与实际结果一致。

### 边界案例

- 文件内容没有日期；
- 两个文件生成相同名称；
- 文件名包含非法字符；
- 文件被其他程序占用；
- 文件类型不支持；
- 文件数量较多；
- 子目录没有授权。

### 系统正确性

- 未确认前不修改文件；
- 不访问授权目录外文件；
- 不覆盖同名文件；
- 取消任务后不继续修改；
- 每个修改都有记录；
- 重复执行不会重复改名。

### 模型质量

- 日期和主题提取准确；
- 新文件名容易理解；
- 无法判断时不胡乱猜测。

系统正确性必须由自动测试保证。模型质量使用固定样例和人工评分检查。

## 10. 本场景的学习目标

- 理解 Tool 如何注册和调用；
- 理解 AgentSession 事件；
- 理解取消信号如何传到 Tool；
- 理解 Session 如何保存工具结果；
- 理解 Skill 如何保存命名规则；
- 理解为什么权限和文件冲突不能交给模型。

## 11. 完成后应产生的规则

本场景完成后，至少确认以下规范是否可用：

- Tool 风险分类；
- 工作目录限制；
- 批量操作预览；
- 用户审批；
- 文件冲突；
- 取消和重复执行；
- 模型质量与系统正确性的分开测试。
