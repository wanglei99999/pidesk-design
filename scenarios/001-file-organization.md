# 场景 001：根据内容批量重命名文件

## 状态

已确认作为 PiDesk 的第一个实现与学习场景。对应任务：[TASK-001](../tasks/TASK-001-file-organization.md)。

## 用户问题

用户收到一批名称混乱的文本资料，需要逐个打开，识别日期、主题和类型，再按统一规则重命名。人工处理耗时，也容易产生遗漏、非法名称和同名冲突。

## 第一版范围

第一版只验证最小闭环：

- 用户明确选择一个本地工作目录；
- 只读取该目录根层级的 UTF-8 `.txt` 和 `.md` 文件；
- 根据文件内容生成新名称；
- 命名格式为 `YYYY-MM-DD_主题_类型.扩展名`；
- 用户查看并确认完整计划后执行重命名；
- 保存原名称、新名称和执行结果。

第一版不移动或删除文件，不读取子目录，不解析 Word、Excel、PPT、PDF，不做定时任务，也不提供完整桌面界面。

## 输入

- 用户授权的工作目录；
- 目录根层级的 `.txt` 和 `.md` 文件；
- 第一版固定的命名规则；
- 用户对预览计划的确认或取消。

测试使用项目生成的模拟文件，不依赖真实私人资料。

## 输出

- 每个文件的原名称、建议名称和判断依据；
- 无法可靠判断的文件及原因；
- 非法名称和同名冲突；
- 用户确认后的逐项执行结果；
- 可检查的新旧名称对照记录。

## Agent 负责

- 从内容中提取日期、主题和资料类型；
- 按固定结构提出新文件名；
- 对缺少关键信息的文件返回“无法判断”，不编造；
- 用户补充缺失信息后重新生成建议。

Agent 只生成结构化建议，不直接获得文件修改权限。

## 确定性程序负责

- 解析并固定工作目录边界；
- 列出允许类型的根层文件；
- 读取文本和采集执行前文件状态；
- 校验模型输出 Schema、文件名和扩展名；
- 检查越界、重复目标和已有目标文件；
- 展示准确的待执行计划；
- 将用户确认绑定到具体的源文件与目标名称；
- 执行前再次检查文件是否变化；
- 只执行已确认的重命名；
- 保存成功、跳过和失败结果。

## Pi 接入候选

本场景用于实际比较：

- coding-agent SDK 是否适合嵌入本地产品流程；
- RPC 是否能提供更清晰的进程与权限隔离；
- `AgentSession`、Tool 调用和事件能否满足结构化计划与取消；
- Pi 类型应该在哪一层被适配，避免扩散到产品核心。

这些都是待验证问题，不预设最终选择。第一版不要求 Session 持久化、Skill 或 Orchestrator。

## 候选 Tool 边界

- `list_workspace_files`：列出工作目录根层允许读取的文件；
- `read_text_file`：读取一个已经通过目录和类型校验的文本文件；
- `validate_rename_plan`：校验结构化建议并返回冲突；
- `apply_approved_rename_plan`：只执行产品层已经确认且执行前复核通过的计划。

最终 Tool 数量和边界以最小代码实验为准。

## 主要风险

| 风险 | 第一版处理 |
|---|---|
| 访问目录外文件 | 解析真实路径并限制在工作目录根层 |
| 模型判断错误 | 展示依据和完整预览，由用户确认 |
| 非法文件名 | 确定性校验，失败项不执行 |
| 同名覆盖 | 预览和执行前都检查，默认不覆盖 |
| 确认后文件发生变化 | 执行前比较文件状态，变化项停止 |
| 用户取消 | 不执行任何重命名 |
| 部分操作失败 | 停止剩余操作，分别记录成功、失败和未执行项 |

## 验收标准

### 系统正确性

- 未确认前不修改任何文件；
- 取消后不修改任何文件；
- 只读取工作目录根层的 `.txt` 和 `.md`；
- 不能通过模型输出访问或修改目录外文件；
- 已有目标、重复目标、非法名称和变化文件不会被覆盖或误改；
- 执行内容与用户确认的计划一致；
- 对照记录与实际文件状态一致。

系统正确性使用固定模型响应或 faux provider 自动验证。

### 模型质量

- 日期、主题和类型能从固定样例中正确提取；
- 建议名称符合给定规则并容易理解；
- 缺少关键信息时返回无法判断。

模型质量使用固定样例人工评估，与系统自动测试分开。

## 可复用能力

完成后应得到：

- 工作目录边界；
- 受限文件读取；
- 结构化 Agent 计划；
- 预览与确认；
- 已确认副作用执行；
- 文件冲突和变化检测；
- 运行结果记录。

## 学习目标

- 用代码比较 Pi SDK 与 RPC 的产品接入边界；
- 理解 AgentSession、Tool 和事件的实际调用链；
- 理解模型建议、程序校验、用户授权和副作用执行的职责分工；
- 验证取消如何传递到 Agent 与 Tool；
- 形成第一批有代码和测试依据的开发规则。
