# ADR-0002：分离公开产品与私有适配

- 状态：已采纳
- 日期：2026-07-30
- 相关产品决定：[产品决定](../../product/decisions.md)
- 取代：无
- 被取代：无

## 背景

PiDesk 是独立开发的公开产品，使用公开资料、模拟数据和标准服务验证通用办公场景。未来可能在公司环境中复用这些能力并连接内部系统。

公司接口、凭据、内部规则和真实数据不能进入公开仓库。如果公开产品直接依赖某个内部系统，会破坏产品独立性，也会增加泄露风险。

## 决定

公开仓库只保存产品核心、通用场景、公共能力、公开资料、模拟数据和脱敏样例。

公司身份、权限、凭据、内部接口、业务规则和真实数据只能在经过批准的私有环境中适配。私有适配不得成为公开产品运行、测试或发布的前置条件。

当前不为未知内部系统提前设计连接器接口。只有公开产品或已确认适配出现实际需求时，才提取最小公共边界。可以反馈到公开仓库的改进必须已经移除内部信息，并能由通用场景独立验证。

## 原因

- 保持 PiDesk 的产品目标和开发节奏独立；
- 保护内部信息和用户数据；
- 避免根据未知需求提前抽象；
- 让已验证的通用能力可以在不同环境复用；
- 保持公开项目适合学习、协作和作品展示。

## 影响

### 正面影响

- 公开产品可以独立开发、测试和发布；
- 私有适配范围清楚；
- 降低误提交内部信息的风险；
- 实际需求出现后，可以复用核心能力而不是重写场景。

### 代价和限制

- 公开产品不能用私有环境作为唯一验证条件；
- 私有适配需要单独维护凭据、安全和兼容性；
- 通用测试通过不代表私有环境验收通过；
- 只有出现真实差异后才能提取稳定接口。

## 考虑过的方案

### 在公开仓库中通过配置区分环境

实现简单，但配置错误、提交历史和调试日志仍可能泄露内部信息，风险不可接受。

### 以内部需求作为公开产品主线

短期目标明确，但会让 PiDesk 依赖不可公开、不可稳定复现的条件，不符合独立产品定位。

### 提前设计完整适配框架

看似便于复用，但当前缺少真实接口差异作为依据，容易产生无用抽象。

## 重新评估条件

- 公开产品不再维护；
- 实际适配证明当前边界无法工作；
- 法律、安全或部署要求发生变化；
- 出现多个已验证的私有适配，需要提取新的公共接口。
