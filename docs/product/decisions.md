# 产品决定

本文件只记录产品目标、范围和优先顺序。技术架构写入 ADR，开发流程写入 `DEVELOPMENT.md`，任务进度写入 `TASKS.md` 和具体任务文件。

## 当前决定

### 项目目的

1. 独立完成一个可以实际使用并持续扩展的办公 Agent 产品；
2. 在真实场景中学习 Pi、Agent 产品设计和工程实现；
3. 将可公开的产品判断、架构、实现和验证整理成个人作品；
4. 公司出现合适需求时，可以复用已经验证的通用能力。

### 产品定义

- 公开产品名称为 DeskBuddy，代码目录、包名和内部标识可以继续使用 `pidesk`；
- DeskBuddy 是由 Pi 驱动的开源本地桌面 Agent 工作台，不是 Pi 的官方前端，也不复制 Pi CLI；
- Coding Agent 是基础能力，文档、表格和其他办公能力在公共任务链路上逐步扩展；
- 任务承载一次用户目标及其执行状态，工作区保存用户授权的文件、规则、对话和产物；
- Skill 封装可复用的工作方法，连接器提供对外部系统的受控访问；
- 产物、变更预览、确认和执行记录是任务结果的一部分，不能只返回聊天文字；
- 助理或专家是角色、默认上下文、Skill 和工具的组合，不是独立的 Agent 内核；
- 项目是在共享工作区中组织多个相关任务，自动化是在稳定手动任务上增加触发和交付规则。

### 产品与运行时边界

详细技术决定见 [ADR-0004](../architecture/decisions/0004-compose-capabilities-above-pi.md)。

- DeskBuddy 产品壳负责任务、工作区、会话界面、审批、产物、权限和产品持久化；
- Pi Runner 是唯一 Agent 执行器，负责模型循环、Tool 调用、Pi 会话、Skill 和 Extension；
- DeskBuddy 能力包可以组合受控 Tool、确定性服务、第一方 Skill/Extension 和声明式界面；
- 不把完整办公功能等同于 Pi Extension，文件格式处理、外部系统调用和确定性校验由产品服务或受控 Tool 完成；
- Renderer 不执行任意 Extension 代码，也不接受 Extension 提供的任意界面；
- V1 只加载 DeskBuddy 明确注册和审查的资源，不开放任意第三方扩展市场。

### 产品范围

- 逐步覆盖文件、文档、表格、网页、消息和自动任务等常见办公场景；
- 首个产品切片是只读代码工作区，先验证真实本地目录、Pi 执行、流式结果、取消和重启恢复；
- WorkBuddy 是当前重点参考产品之一，但不是唯一范围；
- 研究市面产品公开的业务场景、能力组织和用户结果；
- 不研究、猜测或复制产品内部实现；
- 不照抄现有产品表现；
- 可以在通用能力之外增加自己的需求。

### 产品独立性

- DeskBuddy 是独立产品，不是等待公司需求后才开始的内部项目；
- 当前功能、架构和完成标准由 DeskBuddy 的用户问题决定；
- 公司复用是可选的后续路径，不是公开产品的前置条件；
- 不为尚未出现的公司系统提前建设适配层。

### 推进顺序

- 先验证 Pi 接入和最小运行闭环，再完成只读代码工作区纵向切片；
- 以任务、工作区、能力调用、产物、确认和记录组成的公共链路为主线；
- 场景用于验证和扩展公共链路，不直接等同于独立按钮、小工具或产品模块；
- 技术实验可以使用收窄的模拟任务，但不能代替首个产品切片；
- 每个场景都应增加可以被后续场景复用的公共能力；
- 场景顺序根据复杂度、复用价值和学习价值调整；
- 优先级由用户价值、复杂度、复用价值和学习价值共同决定；
- 外部临时需求可以成为候选场景，但不能取代范围分析和验收。

### 公司复用

- 个人开发阶段使用公开资料、模拟数据和标准接口；
- 公司出现需求时优先复用已经完成的通用场景；
- 公司身份、权限、系统和业务规则在批准的私有环境中适配；
- 只有不涉及公司信息的通用改进才能反馈到公开仓库。

## 公司适配时确认

以下事项不阻塞通用版本开发：

- 公司行业和业务特点；
- 使用部门和实际岗位；
- 现有内部效率软件的功能和技术栈；
- 需要连接的内部系统；
- 部署和模型使用限制；
- 第一批试用人员；
- 公司允许公开的内容范围。

## 产品决定变更规则

- 产品目标、范围或优先顺序改变时，更新“当前决定”并在下表追加记录；
- 技术架构改变时创建新的 ADR，不在本文件记录技术方案；
- 开发流程改变时更新 `DEVELOPMENT.md` 或 `AGENTS.md`；
- 当前任务改变时更新 `TASKS.md` 和任务文件。
