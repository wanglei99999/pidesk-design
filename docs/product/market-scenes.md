# 市场办公场景

## 目的

本文件整理市面 Agent 产品中反复出现的业务场景，用于决定 DeskBuddy 做什么。单个产品的资料保存在 `docs/research/products/`，这里不记录或猜测竞品内部实现。

当前已整理：

- [WorkBuddy 公开场景](../research/products/workbuddy.md)。

后续增加产品时，应先记录产品公开事实，再把跨产品共性补充到本文件。

## 场景选择原则

优先选择：

- 输入、输出和完成标准清楚；
- 可以使用公开或模拟数据；
- 结果可以自动检查或人工明确判断；
- 出错后可以停止或恢复；
- 能为后续场景增加公共能力；
- 可以在较小范围内完成第一个可运行版本。

不因为页面复杂、模型数量、多 Agent 或演示效果提高优先级。

## 用户任务场景

| 类别 | 代表性场景 | 可积累的公共能力 | 候选顺序 |
|---|---|---|---:|
| 代码开发 | 理解代码库、搜索实现、解释问题、提出修改方案 | 真实工作区、文件读取、会话、流式事件、取消和恢复 | 1 |
| 文件处理 | 识别、分类、重命名、格式转换 | 文件读取、预览、确认、冲突处理 | 2 |
| 文本与会议 | 摘要、会议纪要、行动项 | 长文本、结构化输出、来源对应、结果校验 | 3 |
| 文档制作 | Word、报告、通知、方案 | 模板、版本、文件生成、预览、多轮修改 | 4 |
| 表格分析 | Excel、CSV、统计和图表 | 结构化数据、确定性计算、图表、校验 | 5 |
| 网络调研 | 搜索、来源整理、研究报告 | 浏览器、来源追踪、去重、上下文控制 | 6 |
| 演示文稿 | PPT 生成和修改 | 模板、渲染、视觉检查、多轮编辑 | 7 |
| 消息与日程 | 邮件、日历、IM | 身份、外部写入、发送确认 | 8 |
| 内容运营 | 选题、资料整理、跨渠道内容 | 多媒体处理、模板和批量生产 | 9 |
| 本地小工具 | 根据自然语言生成并运行临时工具 | 代码执行、依赖和文件权限 | 10 |

顺序是当前技术建议，不是固定路线。实际任务以 [TASKS.md](../../TASKS.md) 为准。

## 跨场景产品能力

以下内容不是与“文档处理”并列的用户场景，而是组合和运行场景的产品能力：

| 能力 | 作用 | 引入条件 |
|---|---|---|
| 任务与工作区 | 保存目标、上下文、状态、文件和产物 | 第一个产品纵向切片 |
| Skill | 固化重复出现的工作方法和工具组合 | 方法经过任务验证后 |
| 连接器 | 受控访问文档、邮箱、数据库等外部系统 | 本地任务稳定后先接只读服务 |
| 助理或专家 | 组合角色、默认上下文、Skill 和工具 | 出现稳定的领域组合后 |
| 自动化 | 为稳定任务增加触发、重试和结果交付 | 手动流程稳定后 |
| 远程入口 | 从消息渠道发起任务并接收结果 | 身份、权限和离线状态明确后 |
| 项目协作 | 在共享工作区组织任务、成员和权限 | 单人任务系统稳定后 |
| 多 Agent | 拆分、并行和汇总复杂任务 | 单 Agent 存在可测量瓶颈后 |

## 当前验证与产品切入口

1. TASK-001 使用文本文件批量重命名作为受控实验，验证 Pi 接入、Tool、预览确认、安全写入和执行记录。它不是首个完整产品功能；
2. 第一个用户可感知的产品切片是“只读代码工作区”：选择真实代码目录，通过自然语言搜索和理解代码，查看流式结果，并在重启后恢复任务；
3. 文档资料处理与生成是代码工作区闭环稳定后的首个办公能力候选；
4. 后续场景根据已经验证的公共链路和实际用户价值决定，不按页面菜单逐项复制市面产品。

## 添加市场资料

新增产品资料时：

1. 只使用产品官方或可核验的公开资料；
2. 记录访问日期；
3. 区分产品事实与 DeskBuddy 分析；
4. 不使用单次模型输出推断实现；
5. 不复制产品文案、界面和内部设计；
6. 只把跨产品共性补充到本文件。
