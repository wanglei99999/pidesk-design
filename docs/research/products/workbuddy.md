# WorkBuddy 公开场景记录

## 说明

本文件根据 WorkBuddy 官方文档和公开页面整理，访问日期为 2026-07-30。WorkBuddy 是首个研究样本，不是 PiDesk 的功能边界。

场景和功能描述来自公开资料；以“PiDesk 分析”开头的段落属于本项目判断，不代表 WorkBuddy 的实现方式。

## 官方实践案例

WorkBuddy 当前文档目录列出了 11 个实践案例：

1. 文件内容识别与处理；
2. 文档生成与编辑；
3. 数据分析并可视化；
4. 自媒体运营；
5. 每日自动推送资讯简报；
6. 远程遥控 WorkBuddy；
7. 零代码制作本地应用；
8. 创建自己的 Skills；
9. 让 Agent 自主拆分并完成复杂任务；
10. 管理会议；
11. 管理腾讯文档。

下面按照工作类型重新整理，供 [市场办公场景](../../product/market-scenes.md) 提取跨产品的共性需求。

## 基础办公

### 文件内容识别与处理

- 按内容或文件属性批量重命名；
- 整理合同、票据、图片和资料；
- 根据会议记录生成会议纪要；
- 从字幕或视频中提取内容、翻译并生成摘要；
- 对高风险批量修改先生成预览，再由用户确认。

PiDesk 分析：这类场景通常需要文件读取、内容解析、批量操作、冲突检查和操作记录。

### Word 和 PPT

- 根据目标和结构生成通知、方案、制度、申请和汇报材料；
- 根据已有材料、大纲和模板生成 PPT；
- 在已有文件上继续修改，而不是每次重新生成；
- 按受众、页数和风格调整结果。

PiDesk 分析：这类场景通常需要 Office 文件读写、模板、预览、版本管理和多轮修改。

### 数据分析

- 读取 Excel、CSV 等数据；
- 按时间、部门、产品等维度统计；
- 生成柱状图、折线图等图表；
- 根据统计结果生成报告；
- 从多个公开来源搜集数据后再分析。

PiDesk 分析：这类场景通常需要表格解析、数据计算、绘图、结果校验和文件生成。

### 网络调研

- 搜集指定时间范围内的公开信息；
- 进行行业、竞品和市场研究；
- 整理来源、去重并生成报告；
- 在输出前检查重复和缺失内容。

PiDesk 分析：这类场景通常需要搜索、网页读取、来源记录、信息筛选和报告生成。

### 内容运营

- 选题和资料收集；
- 图文内容生成；
- 图片、视频等多媒体处理；
- 按渠道要求调整内容；
- 批量生产和后续修改。

PiDesk 分析：内容运营只有在存在稳定生产需求时才值得优先开发，不能只因为容易演示就提高优先级。

### 快速制作内部小工具

- 用自然语言描述一个本地应用；
- 生成、运行和调试代码；
- 根据使用反馈继续修改；
- 把临时脚本逐步做成可重复使用的小工具。

PiDesk 分析：这类场景和 Pi 原本的编程用途接近。面向非技术用户开放时，需要限制代码执行、依赖安装和文件访问范围。

## 自动执行和远程使用

### 自动任务

- 每日资讯简报；
- 周报和日报汇总；
- 定期整理数据和文件；
- 在指定时间、工作目录、模型和 Skill 下执行；
- 保存执行记录，并按需推送结果。

PiDesk 分析：实现时需要调度、并发限制、超时、身份、凭据、运行历史和失败提醒。自动任务必须先手动跑通。

### 远程助理

- 通过微信、企业微信、QQ、钉钉或飞书发起任务；
- 不在电脑前时继续处理本地文件；
- 将执行结果返回移动端；
- 对高风险操作采用更严格的确认方式。

PiDesk 分析：这类场景需要消息平台接入、用户身份绑定、任务路由、结果回传和离线状态处理。

## 外部系统和知识

### 连接器

官方文档列出的用途包括：

- 查询数据库和文档；
- 发送邮件、创建日程；
- 读取和上传云端文件；
- 发送企业微信或飞书消息；
- 通过 OAuth 或 API 密钥访问第三方服务；
- 安装自定义 MCP 服务。

PiDesk 分析：连接器的读操作和写操作应分开授权，凭据不能交给模型直接处理。

### 在线文档与会议

- 搜索、创建和整理腾讯文档；
- 汇总多人协作内容；
- 查询文档权限；
- 管理会议和整理会议纪要；
- 把会议内容沉淀到文档或知识库。

PiDesk 分析：同一场景可以适配不同在线文档、会议和办公系统。

### 知识库和记忆

- 检索个人或企业资料；
- 将任务与指定知识库关联；
- 保存用户长期偏好和必要信息；
- 区分当前任务上下文、长期记忆和企业知识。

PiDesk 分析：知识库不是第一阶段必做项。只有资料规模、访问权限和检索目标明确后再设计。

## 专业角色和协作

### Skill

- 封装特定工作的步骤、工具和参考资料；
- 让用户安装、选择和管理；
- 支持版本、安全检查和按需加载；
- 适合周报、会议纪要、文档制作等重复方法。

### 专家

- 为 Agent 配置角色、工作方法和工具；
- 适合一个明确领域的问题；
- 专家本身不应自动获得额外系统权限。

### 专家团

- 由负责人拆分任务；
- 多个角色分别执行；
- 汇总结果并交付；
- 适合确实可以分工的复杂任务。

PiDesk 分析：多 Agent 会增加模型调用、状态管理和结果冲突。第一阶段不实现。

### 项目协作

WorkBuddy 公开内容还包括项目、任务协作、文件资产、计划看板、成员权限和任务移交。

PiDesk 分析：这些能力已经超出单人 Agent 范围，属于团队工作系统，应在单人任务成熟后再考虑。
